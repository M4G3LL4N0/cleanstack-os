# Autobuilder Guardrails

## Product Truth
CleanStack OS is a premium workstation-health and safe cleanup intelligence product for overloaded local machines. It is not a generic SaaS dashboard, not a cybersecurity product, not a cloud backup app, and not a Noaerth portfolio page.

## Public Positioning
Describe it as a safe, workflow-aware system for identifying, archiving, and cleaning unnecessary files across dev, creative, and AI workflows.

## Do Not Expose
Do not expose private local paths except generic examples. Do not expose internal Autobuilder mechanics as public product claims. Do not claim real destructive cleanup exists in the web app if it is only a demo. Do not expose secrets or .env values.

## Do Not Delete
Preserve source, app routes, components, lib, public assets used by the site, data/waitlist.json, package.json, pnpm-lock.yaml, config files, docs, .env.example, .env.local, .git, .gitignore, RECOVERY_NOTES.md, AUTOBUILDER_FOUNDATION.json, and .autobuilder.

## Do Not Drift Toward
Avoid Noaerth visuals, generic SaaS templates, unrelated startup concepts, fake AI claims, automatic dangerous deletion, or random design overhauls that erase the CleanStack identity.

## Safe Improvements
Build fixes, responsive polish, copy clarity, SEO, route consistency, admin UX, app shell polish, cleanup demo clarity, graphics optimization, documentation, foundation file updates.

## Risky Improvements
Real file deletion, auth/database migrations, Supabase conversion, changing stack, deleting assets, removing pages, changing product category, deploying, pushing to GitHub.

## Build Rules
Use pnpm only. Do not use npm. Do not deploy automatically. Do not push automatically. Prepare for manual Vercel deploy only.
